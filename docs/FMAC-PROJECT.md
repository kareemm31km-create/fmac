# موقع قسم الإعداد الفني — نادي الفجيرة للفنون القتالية (FMAC)

> ملف تعريف المشروع. يُقرأ أولاً في أي جلسة جديدة قبل أي تعديل.

---

## 1. المشروع في سطر

موقع إدارة كامل لقسم الإعداد الفني في نادي الفجيرة للفنون القتالية: متابعة تنفيذ الخطط
التدريبية الأسبوعية، نتائج البطولات والمواسم، الزيارات الميدانية، كالندر مشاركات الموسم،
والتقارير — واجهة عربية RTL مع خيار تحويل كامل للإنجليزية.

**صاحب المشروع:** كريم زاهر — المدير الفني للقسم.

---

## 2. القيود الثابتة (لا تُخالَف)

| القيد | التفصيل |
|---|---|
| **بلا تكلفة مالية** | «لو الموضوع فيه تكلفه مالية ما تعملهوش». كل شيء على الطبقة المجانية: Google Apps Script + استضافة ساكنة مجانية. |
| **لا إصابات ولا لاعبين** | نموذج الخطط والتدريب لا يتضمّن إصابات ولا أسماء لاعبين. (استثناء وحيد: لاعبو المنتخب الوطني — بطاقة مستقلّة.) |
| **العربية الفصحى** | كل نصوص الواجهة بالفصحى، بلا عامية مصرية. |
| **التقييم للإدارة فقط** | المدرب يقرأ ولا يقيّم. `user.admin` يحكم كل إجراء تعديل. |
| **اسأل قبل كل ميزة** | يُعرض الشكل المتخيَّل قبل التنفيذ، ولا تُضاف ميزة بلا طلب. |
| **الصدق في الأرقام** | لا رقم مُخترَع. ما لا يُقاس يُعرض `—` لا `0`. وكل مقارنة تذكر تغطيتها. |

## 3. المعمارية

```
المتصفّح (ملف HTML واحد)  ←→  Google Apps Script Web App  ←→  Google Sheet
        ↑                              ↑                          ↑
   الواجهة كلها              doGet (JSON) / doPost           التخزين الفعلي
   + localStorage                                             (23 تبويباً)
   (كاش وهوية الجهاز)
```

- **لا خادم ولا قاعدة بيانات.** جدول جوجل هو قاعدة البيانات، وApps Script هو الـAPI.
- **الموقع ملف واحد** `index.html` (~1.8 ميجا) فيه كل شيء: CSS وJS والأيقونات
  والشعار وبيانات المواسم — مضمّنة كنصّ أو Base64. لا طلبات خارجية إطلاقاً
  (الخطوط بديلها نظامي).
- **PWA**: `manifest.json` + `sw.js` (شبكة أولاً، والكاش احتياطي) — يشتغل داخل الصالة بلا نت.

### ربط الجهاز بالجدول
الموقع يُبنى بعنوان API فارغ. يُربط الجهاز مرّة واحدة بفتح:
```
https://<الموقع>/?api=<رابط-AppsScript>&u=<الكود>
```
يُحفظ العنوان في `localStorage['fmac.api']` وينظّف الرابط نفسه. **روابط دعوة المدربين
تُولَّد تلقائياً حاملةً العنوان** من صفحة الإعدادات ← المستخدمون.

## 4. الملفات (بيئة العمل)

| الملف | الدور |

| `page.html` | **المصدر الوحيد للواجهة** (~14,270 سطراً). فيه placeholders تُستبدَل عند البناء. |
| `build.py` | يبني `site/index.html` + الأيقونات + manifest + sw + `FMAC-site.zip`. الوسيط الاختياري = عنوان API. |

| `plans.json` · `icons.json` · `brand.json` | الخطط · الأيقونات · هوية العلامة. |
| `logo_dark_b64.txt` · `pattern_b64.txt` | أصول Base64. |
| `extract_seasons.py` · `extract_local_2526.py` · `extract_scopes_2526.py` | استخراج المواسم من ملفات الإكسل. |

### الـplaceholders في `page.html`
`__LOGO_DARK__` · `__PLANS__` · `__ICONS__` · `__BRAND__` · `__SEASONS__` · `__PATTERN__` · `__API_URL__`

### تشغيل بيئة التطوير
```bash
python3 mock_api.py                       # :8902 محاكي الـAPI
python3 -m http.server 8903 --directory site
python3 build.py 'http://127.0.0.1:8902/' # بناء للتطوير
python3 build.py                          # بناء للإنتاج (API فارغ)
```

| القسم | الصفحات |

*(العرض الموسّع `PRO` يضيف: المدربون · سجل التدقيق.)*

### الرئيسية — بترتيبها
1. **شريط علوي**: عنوان الصفحة + ترحيب · شارة حمراء «N عناصر تحتاج مراجعتك» · الموسم · الأسبوع · الفرع · الجرس.
2. **أربع بطاقات مؤشّرات**: الأداء العام (حلقة قياس مفتوحة من الأسفل) · الخطط المستلمة · الخطط المعتمدة · تنفيذ الخطط.
3. **صف**: بطاقة الميداليات (رقم كبير + ذهبية/فضية/برونزية + فرق الموسم + أفضل ثلاث ألعاب) — وبجانبها **بطاقة منتخب الإمارات** بعلم مموّج مدموج.
4. **ثلاث بطاقات**: أجندة القسم (أقرب المواعيد) · منحنى تطوّر الأداء متعدّد الخطوط (مدى 4/8/12/الكل) · أداء القسم الفني (6 صفوف).
5. **كالندر الموسم**: عدّادات · شريط شهور · بطاقات البطولات · مفتاح الحالات.
6. **آخر المتابعات الفنية**: أربع بطاقات.

### صفحة اللعبة — أربعة مستويات
Hero (رقم الميداليات والقصّة) → 5 مؤشّرات → تحليلات ومقارنة المواسم → تفاصيل
(إنجازات · دروع · أفضل 5 بطولات ثم جدول قابل للبحث · معسكرات · المنتخب · أسلحة/جنس).
تبويبات ثابتة: نظرة عامة · النتائج والإنجازات · الخطط · المدربون.
النطاقات: محلي · دولي · منتخب. **الدروع للمحلي وحده.**

### كالندر الموسم
- الحالات: `قادمة` (أزرق) · `مؤكدة` (أخضر) · `مؤجّلة` (كهرماني) · `ملغاة` (أحمر) · `انتهت` (رمادي).
- **التأجيل**: الضغط على البطولة ← اختيار «مؤجّلة» ← تاريخ جديد (اختياري) + سبب.
  البطاقة تعرض التاريخ الأصلي مشطوباً والجديد بجانبه، وتُرتَّب بالتاريخ الجديد.
- **استيراد كشف اتحاد**: لصق صفوف Excel — الترتيب: التاريخ · البطولة · اللعبة · النطاق · الاتحاد · المكان.
  يقبل `2026-09-12` و`12/09/2026`، ويعرض معاينة وتنبيهات قبل الاستيراد.

### الفروع والألعاب

## 8. الترجمة (عربي ⇄ إنجليزي)

`applyLang()` تمشي على نصوص الـDOM بـTreeWalker، ثم:
1. `DICT` — عبارات كاملة
2. `RULES` — تعابير نمطية بـ`$1`
3. `trTokens` — كلمات مفردة (`SPORT_EN` `DAY_EN` `MON_EN` `MISC_EN`)

- `MutationObserver` يعيد التطبيق على أي محتوى جديد.
- `[data-raw]` على أي عنصر ⇐ **لا يُترجَم** (أسماء البطولات والاتحادات التي يكتبها المستخدم).
- استبدال `MISC_EN` يحترم حدود الكلمة العربية (منع «الأسبوعية» ← «Weekية»).

> **عند إضافة أي نصّ عربي جديد أضف ترجمته**، وشغّل `/tmp/en.js` للتأكّد أن المتبقّي بيانات مستخدم فقط.

## 9. أخطاء اتصلحت — لا تتكرّر

| الخطأ | السبب والعلاج |
|---|---|
| **الحفظ لا يعمل إطلاقاً** | متغيّر `history` (سجلّ الأسابيع) كان يحجب `window.history`، فرمى `ReferenceError` في التمهيد وابتلعه `catch` فاضٍ ⇒ عنوان API فارغ ⇒ **وضع تجريبي صامت**. العلاج: `window.history.replaceState` صراحةً، وفصل تنظيف الرابط في `try` مستقلّ بعد حفظ العنوان. |
| **صفحات بمقاسات مضروبة** | `</div>` زائد في «صندوق المراجعة» أغلق `.wrap` مبكّراً ⇒ أربع صفحات (الخطط · الأرشيف · التدقيق · الإعدادات) خارج التخطيط. |
| **بطاقات بارتفاع 46px** | تصادم أسماء: `.calc` كانت مستعملة أصلاً لخلايا التقويم (`height:46px`). كل أصناف كالندر الموسم صارت بسابقة `sc-`. |
| **`kparts(k).planId`** | الصحيح `.pid` — كان يصفّر الشدة والحجم والأهداف بصمت. |
| **بصمة الحصة لا تُحفَظ** | شاشة المتابعة كانت تجمع الشدة والهدف ثم ترميهما. أُضيف `saveFingerprint()`. |
| **معرّف DOM مكرّر `wkChart`** | رسم التقارير لم يُنفَّذ إطلاقاً ⇒ صار `wkChart2`. |
| **فلاتر لا تفتح** | `.filters{overflow:hidden}` كانت تقصّ القائمة. |
| **تصادم `fillSel`** | دالة موجودة بتوقيع مختلف ⇒ سُمّيت `optFill`. |
| **مقارنة مواسم مضلِّلة** | موسمان بتغطية ألعاب مختلفة ⇒ `seasonsShared()` + ملاحظة تغطية صريحة. |
| **روابط الدعوة بلا عنوان الجدول** | كل مدرب كان يقع في الوضع التجريبي ⇒ `inviteLink()` تحمل `?api=...&u=...`. |
| **نشر Apps Script قديم** | الإجراءات الجديدة كانت تسقط في `saveTicks_` وترجع `ok:true` بلا حفظ ⇒ حارس `unknown_action` + رقم `BUILD`. |

## 10. النشر

**أ — Apps Script**
1. جدول جوجل ← الإضافات ← Apps Script ← الصق `FMAC-Apps-Script.gs`
2. شغّل `setup()` (ينشئ التبويبات الناقصة وكودَي الإدارة)
3. نشر ← إدارة عمليات النشر ← تعديل ← **إصدار جديد** ← انسخ الرابط

**ب — الموقع** (`FMAC-site.zip` — ستة ملفات في الجذر)
- استضافة مجانية ساكنة: **GitHub Pages** (repo عام ← Settings ← Pages ← main / root)
  أو **Cloudflare Pages** (Workers & Pages ← Upload assets).
- ❌ Netlify: الحساب تجاوز حدّ الاستخدام والنشر مقفول.
- المسارات كلها نسبية ⇒ **يعمل من مجلد فرعي** (`user.github.io/fmac/`) — مُختبَر.

**ج — بعد النشر**
1. افتح مرّة واحدة: `<الموقع>/?api=<AppsScript>&u=admin1`
2. الإعدادات ← المستخدمون ← **انسخ روابط المدربين من جديد** (تحمل العنوان الجديد)

**أكواد الإدارة** (يُنشئها `setup()` في تبويب المستخدمين):
`admin1` = كريم زاهر · `admin2` = المشرف الفني — تُعدَّل من داخل الموقع.

**شريط التحذير الأحمر** يظهر تلقائياً لو الموقع غير مرتبط أو النشر قديم، ويشرح الخطوة الناقصة.
